Candidate Assistant: Architecture

Read-only "ask about candidates" app built on top of the CV pipeline's state.db. Runs entirely on this laptop.

Request flow

  1. User types a question in the Streamlit chat.
  2. LangGraph sends it, with chat history, to qwen3:4b, which picks one tool and its parameters.
  3. Parameters are validated. If invalid, the model retries or asks the user to clarify.
  4. The tool runs a fixed, read-only SQL query on state.db.
  5. qwen3:4b writes a short answer from the returned rows.
  6. The UI shows the answer, a results table and CV links.

Safety by design

  • Database opened read-only, so nothing can be changed.
  • The model never writes SQL; it only fills tool parameters.
  • All values bound as query parameters, never pasted into SQL.
  • Everything runs locally; no candidate data leaves the laptop.

Planned files (folder LangGraph)

  • app.py: Streamlit UI
  • agent.py: LangGraph graph
  • tools.py: controlled SQL tools
  • db.py: read-only connection
  • state.db: data snapshot from the pipeline
